# S3 object-storage destination

> **Status**: SHIPPED in #96 Phase B. The dispatcher writes one
> newline-delimited JSON object per audit row to an S3-compatible bucket via
> the `object_store` crate.

## Configuration

`POST /audit/destinations` (admin-only):

```json
{
  "name": "audit-archive",
  "kind": {
    "type": "s3",
    "bucket": "my-audit-bucket",
    "prefix": "audit",
    "region": "us-east-1",
    "partition": "by_date_and_org"
  }
}
```

- `bucket`: S3 bucket name.
- `prefix`: key prefix inside the bucket. Leading + trailing slashes are
  normalized (`/audit/` and `audit` are equivalent).
- `region`: AWS region code (`us-east-1`, `eu-west-2`, etc.). For self-hosted
  S3-compatible backends (MinIO, R2, Wasabi), the region is informational —
  the endpoint comes from the override hook below.
- `partition`: key-layout strategy.

## Partition strategies

| Strategy            | Key pattern                                              |
|---------------------|----------------------------------------------------------|
| `by_date`           | `<prefix>/YYYY/MM/DD/<audit_id>.jsonl`                   |
| `by_org`            | `<prefix>/org=<org_id>/<audit_id>.jsonl`                 |
| `by_date_and_org`   | `<prefix>/org=<org_id>/YYYY/MM/DD/<audit_id>.jsonl`      |

`<org_id>` falls back to the literal string `global` for deployment-wide
events (no `organization_id` in the audit metadata). The memory backend
stores org scope in `metadata.organization_id`; SQL backends can materialize
this as a column when their repos land.

## Authentication

Production AWS deployments: the dispatcher constructs the S3 client via
`object_store::aws::AmazonS3Builder::from_env()`, which reads the standard
SDK environment variables:

```
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_SESSION_TOKEN=...   # optional, for IAM-role credentials
AWS_REGION=...          # destination's `region` overrides this
```

Credentials are never logged.

## Self-hosted S3-compatible backends

For MinIO, Cloudflare R2, Wasabi, Backblaze B2, or any other
S3-compatible store, construct a fully configured `AmazonS3` at startup
and install it via the override hook:

```rust
use yauth::plugins::audit_export::destination::set_s3_object_store_override;
use std::sync::Arc;

let minio = object_store::aws::AmazonS3Builder::new()
    .with_endpoint("https://minio.internal:9000")
    .with_access_key_id(std::env::var("MINIO_ACCESS_KEY")?)
    .with_secret_access_key(std::env::var("MINIO_SECRET_KEY")?)
    .with_region("us-east-1")
    .with_bucket_name("audit-bucket")
    .with_allow_http(true) // intranet only
    .build()?;
set_s3_object_store_override(Some(Arc::new(minio)));
```

The override is process-wide; production deployments install it once at
startup. To clear, pass `None`.

## Body format

```json
{"id":"...","timestamp":"...","event_type":"user.login","user_id":"...","ip_address":"...","metadata":{...}}
```

Each object holds a single record terminated by `\n`, which makes
concatenation produce valid newline-delimited JSON. The dispatcher writes
one record per object today; the suffix is `.jsonl` so future batched
writes can store multiple records per key without breaking the contract.

## Failure semantics

| Outcome | Dispatcher action | Worker action |
|---|---|---|
| Authentication failure / `403 AccessDenied` | `DispatchError::Transport("s3 put: ...")` | retry per backoff, dead-letter after 5 |
| Network failure / timeout | `DispatchError::Transport(...)` | retry, dead-letter after 5 |
| Successful PUT | `Ok(())` | mark sent |

Errors are scoped to the destination via the surrounding worker — one
broken S3 destination never blocks the other dispatchers.

## Test coverage

Three pentests in `crates/yauth/tests/audit_export_pentest.rs`:

- `pentest_s3_round_trip_by_date` — asserts the key matches
  `audit/YYYY/MM/DD/<uuid>.jsonl`.
- `pentest_s3_round_trip_by_org` — asserts the key embeds `org=<uuid>`
  pulled from the audit's `metadata.organization_id`.
- `pentest_s3_round_trip_by_date_and_org` — asserts both prefixes are
  combined.

All three use `object_store::memory::InMemory` and the
`set_s3_object_store_override` hook — never a real S3 bucket.
